# دليل التخصيص

## الهوية

ابدأ بـ `teacher.json`: غيّر `appName` و`name` و`professionalTitle` و`specialization` و`bio` و`tagline`. ضع شعارًا وصورة جديدين في `public/assets/brand`، ثم غيّر `photo.src` و`logo.src` ووصف `alt`. يمكن استخدام `null` بدل الصورة أو الشعار، فتظهر الحالة البديلة الآمنة.

`theme` يحتوي الألوان والخط المسمّى. بقي الإخراج الدافئ والتباين والتوزيع البصري، لكن الرسومات الأساسية في القالب عامة ولا تمثل شخصًا أو علامة سابقة. حافظ على تباين `primary` مع `primaryContrast`. بعض الألوان داخل أدوات الرسم والفهرس وظيفية وثابتة وليست مشتقة كلها من لون الهوية.

`contacts` مصفوفة فارغة. أضف عنصرًا مثل المثال الآتي بعد استبدال الرابط بعنوان صحيح تملكه:

```json
{"id":"website","label":"الموقع التعريفي","url":"https://example.com"}
```

العنوان في المثال توضيحي، وليس رابط خدمة جاهزة للمعلم. لا تنشر روابط غير معدّلة. حدّث أيضًا عنوان ووصف `index.html` و`metadata.json` بما يلائم الهوية الجديدة.

## التسلسل التعليمي

`curriculum.json`: `levels → subjects → units → lessons`.
الأسماء مرنة؛ قد يعني المستوى صفًا أو فئة، والمجال مادة أو مسارًا تدريبيًا. لا تغيّر البنية البرمجية لمجرد تغيير المصطلحات المعروضة.

كل معرّف درس فريد على مستوى التطبيق، مثل `lesson-01`. يطابقه الملف `src/data/lessons/lesson-01.json`. عند حذف درس احذف مرجعه وملفه والعناصر المرتبطة به في `unit-index.json` و`lesson-support.json`.

لا تغيّر المعرّفات بعد استخدام التطبيق إلا بخطة ترحيل؛ حالة الإنجاز والروابط ترتبط بها. يمكن تغيير العناوين دون تغيير المعرّفات.

## حقول محتوى الدرس

`explanation.text` نص الشرح، و`explanation.audio` تسجيل اختياري أو `null`. `summary.text` الملخص و`summary.resources` الخرائط والصور والروابط. `videos` للفيديو، و`activities` للأنشطة، و`assessments` للتقويم، و`files` للبوكليت والعروض، و`homework` للواجبات.

الهيكل الفارغ موجود بالفعل في كل ملف درس. لا تكتب HTML تنفيذيًا داخل النصوص. مثال مورد عام بعد إضافة ملف حقيقي إلى المسار المحدد:

```json
{
  "id": "booklet-01",
  "title": "عنوان البوكليت",
  "url": "/assets/resources/booklet-01.pdf",
  "format": "booklet",
  "action": "open"
}
```

**هذا الملف PDF غير مرفق.** أنشئه أو غيّر الرابط قبل إضافة المثال إلى البيانات. يوضع البوكليت في `files` مع `format: "booklet"`. العرض التقديمي في `files` مع `format: "presentation"` أو `"pptx"`. الحقول الأخرى مثل `description` و`thumbnail` اختيارية بحسب العقد في `src/content/schema.ts`.

الفيديو يستخدم `kind: "youtube"` أو `"direct"` أو `"link"`. الصوت المباشر يستخدم `kind: "direct"`. كل رابط خارجي يبدأ بـ HTTPS، أو يكون موردًا محليًا تحت `/assets/`. قد تمنع الخدمة الخارجية التضمين أو تتطلب تعديل صلاحيات الملف؛ لا يعتبر هذا عطلًا في القالب نفسه. عارض البوكليت يعتمد على عرض PDF المتاح في المتصفح، وليس أداة منع نسخ.

## فهرس الوحدة التفصيلي

كل مفتاح في `unit-index.json` يطابق معرّف وحدة. داخله `levelId` و`subjectId` و`unitId`، ثم بيانات العنوان وألوان الشريط و`topics`.

كل موضوع يحتوي `items`، وكل عنصر يشير إلى **معرّف درس موجود بالفعل داخل هذه الوحدة**. `type` يحدد الفئة والأيقونة؛ و`typeLabel` اسم الفئة المعروض. الأنواع المتاحة:

`diagnostic`, `explanation`, `reading`, `listening`, `video`, `activity`, `formative`, `project`, `review`, `writing`.

يمكن إضافة `diagnostic` أو `project` اختياريين على مستوى الوحدة. لا تكرر الدرس في أكثر من موضع. `pageNumber` رقم صفحة اختياري، وليس مطلوبًا عندما لا يوجد كتاب مرجعي.

هذه التصنيفات تصف **عناصر فهرس الوحدة**، ولا تلغي الأقسام التسعة داخل كل درس. إذا أضفت وحدة دون فهرس مخصص، يولّد التطبيق فهرسًا عامًا لدروسها بدل إخفائها. إذا أضفت درسًا جديدًا إلى وحدة لها فهرس، يُعرض ضمن بقية دروس الوحدة إلى أن تصنفه.

في `curriculum-display.json` ضع أغلفة المستويات حسب المعرّف، وكلمات البحث السريعة. البحث يطبّع بعض اختلافات كتابة العربية، ويطابق الكلمات داخل الحقل الواحد دون مزج رقم درس مع اسم مستوى آخر.

## المساعد الموجّه

أضف إلى `lesson-support.json` داخل `guides` كائنًا مفتاحه معرّف الدرس. الحقول: `lessonTitle`, `intro`, `topics`, `quickQuestion`.

كل موضوع مساعد يحتوي `id`, `title`, `explanation`, `simpleExplanation`, `examples`، ثم `commonMistake` الذي يحتوي `wrong`, `correction` و`reason` الاختياري. السؤال القصير يحتوي `question`, `options`, `correctIndex`, `correctFeedback`, `incorrectFeedback` و`hint` الاختياري. يبدأ ترقيم الإجابة الصحيحة من الصفر.

يمكن وضع واجب إضافي داخل `homeworkAssessments` بنفس معرّف الدرس، باستخدام عقد `HomeworkItem` في `src/content/schema.ts`.

المساعد هنا تنقل تفاعلي في محتوى موثوق أُعدّ مسبقًا، وليس دردشة توليدية. لا يحتاج مفتاحًا. تُعرض حالة الفراغ بوضوح عندما لا يُجهّز محتوى الدرس.

## البرامج والتقدم

غيّر جميع تفاصيل البرنامج من `student-programs.json`. الروابط الافتراضية `null`، فتظهر الأزرار كغير جاهزة. لا يوجد تسجيل مدفوع فعلي أو مصادقة. اضبط الحماية لدى الخدمة الحاضنة أو صمّم نظامًا خلفيًا مستقلًا بتكليف صريح.

غيّر `storageNamespace` في `template-settings.json` لكل نسخة مستقلة. استخدم حروفًا إنجليزية صغيرة وأرقامًا وشرطات. تغيير المفتاح بعد بدء الاستخدام يفصل الحفظ السابق، لذلك اختره مبكرًا.

`demoMode: true` يُظهر اختيارات المحاكاة المرتفعة والمنخفضة مع تسميتها بوضوح. `false` يخفيها ويُبقي التقدم المحلي الحقيقي فقط. لا توجد حسابات طلاب أو مزامنة بين أجهزتهم.

## التحقق بعد التخصيص

```bash
npm run validate:content
npm run validate:template
npm run typecheck
npm run test:run
npm run security:scan
npm run build
```

راجع اختبارات البيانات النموذجية عند تغيير عدد الدروس أو معرّفاتها؛ بعض اختبارات الحزمة تتوقع أول وحدة بثلاثة دروس. عدّلها لتختبر البيانات الجديدة، ولا تحذف اختبارات السلوك.

افحص عمليًا: التنقل، فتح الأقسام التسعة، الروابط الحقيقية، الوسائط، اكتمال درس ثم إلغاؤه، مخطط التقدم، إعادة التحميل واستمرار الحفظ، السبورة وأدواتها وتنزيل المشروع وإعادة استيراده، الجوال ولوحة المفاتيح. راجع عدم وجود أسماء أو صور أو روابط غير مقصودة قبل النشر.
